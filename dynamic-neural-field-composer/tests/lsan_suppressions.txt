# LeakSanitizer suppressions for the asan-ubsan CI job (see #155).
#
# The dnf_composer::element:: suppression that used to live here (added
# alongside this file, see #155) is gone: it worked around Element::outputs
# holding a strong shared_ptr back to every downstream element, which formed
# a two-way ownership cycle with Element::inputs and kept both elements alive
# forever whenever they were connected outside a Simulation (exactly the
# fixture pattern most of tests/elements/*.cpp uses). #168 makes `outputs`
# non-owning (std::weak_ptr), which breaks the cycle at the root -- see
# Element::outputs in include/elements/element.h for the ownership contract.

# FFTW3 caches plan-cache ("wisdom") allocations in its own process-global
# state for reuse across calls; LeakSanitizer's conservative scan does not
# always recognize that state as reachable at exit. This is a well-known,
# library-level false positive when running FFTW3 under LSan, unrelated to
# dnf-composer's own code -- suppress by its C symbol prefix rather than by
# call site, since the false positive can originate from any FFTW3 planner
# entry point.
leak:fftw_
