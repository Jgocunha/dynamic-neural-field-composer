# .dnf File Schema

A `.dnf` file is the on-disk serialization of a `Simulation`: its identifier, time step, and every element with its parameters and input connections. Files are plain, pretty-printed JSON (4-space indent, via [nlohmann/json](https://github.com/nlohmann/json)) — open and hand-edit them in any text editor.

This page documents the schema as actually produced and consumed by `SimulationFileManager` (`include/simulation/simulation_file_manager.h`, `src/simulation/simulation_file_manager.cpp`). See [Simulation → Persistence](Simulation#persistence-save--load) for the surrounding save/load API.

---

## Root object

```json
{
    "formatVersion": 1,
    "identifier": "my simulation",
    "deltaT": 1.0,
    "elements": [ /* array of element objects, see below */ ]
}
```

| Key | Type | Written by `saveElementsToJson()` | Read by `loadElementsFromJson()` |
|---|---|---|---|
| `formatVersion` | int | Always the constant `kCurrentFormatVersion` (currently `1`) | Selects the read path — see [Schema version](#schema-version) below. **Optional on read**: absent means version 0. |
| `identifier` | string | `simulation->getUniqueIdentifier()` | Applied via `simulation->setUniqueIdentifier(...)`. Logged as an error and skipped if present but not a string. |
| `deltaT` | number | `simulation->getDeltaT()` | Applied via `simulation->setDeltaT(...)` **only if** it's a finite number `> 0.0`; otherwise logged as an error and the simulation's existing `deltaT` is left unchanged. |
| `elements` | array | Every element in the simulation, one object each (see below) | Each entry reconstructed via the element factory switch in `jsonToElements()`. |

---

## Schema version

The root object declares which revision of this schema it was written against, so a future format change can be migrated deliberately instead of silently misreading old files. The constant lives in one place — `kCurrentFormatVersion` in `include/simulation/simulation_file_manager.h`.

### The versions

| Version | Declared how | Root layout |
|---|---|---|
| **0** | Implicit — no `formatVersion` key at all | Either a **bare JSON array** of element objects (the oldest format, predating any root metadata), or an **object** with `identifier`/`deltaT`/`elements` (every file written before `formatVersion` was introduced). |
| **1** | `"formatVersion": 1` | The object layout above, now declaring its own version. This is what the current build writes. |

Versions 0 and 1 describe the *same* element schema — version 1 adds only the declaration itself. So a version-0 file and a version-1 file with the same elements load identically; nothing about existing files changed.

### How each case is handled on load

| `formatVersion` in the file | Behaviour |
|---|---|
| Absent, root is a bare array | Version 0. The array is treated directly as the `elements` list; `identifier`/`deltaT` keep whatever the `Simulation` was constructed with. Detected by shape, exactly as before. |
| Absent, root is an object with `elements` | Version 0. Loads normally — this is what every pre-`formatVersion` build wrote, and those files are unaffected. |
| `1` | Current format. Loads normally, no message. |
| Greater than `kCurrentFormatVersion` (e.g. `999`) | **Warning, then best-effort load.** Logs a `WARNING` naming both the file's version and this build's — *"this file was written by a newer version of dnf-composer"* — and then loads what it can. Anything the newer format added that this build doesn't recognize is ignored by the existing tolerant paths in `jsonToElements()` (unknown element labels and interactions referencing elements that failed to load are already logged and skipped). A partial simulation plus a clear warning is more useful than an empty one. |
| Not a whole number `>= 0` (a string, a float like `1.5`, a negative) | **Rejected as malformed input**, the same way any other structurally invalid root is: logs `Invalid simulation file: "formatVersion" must be a whole number >= 0: <path>` and the load aborts without modifying the simulation (no elements added, `identifier`/`deltaT` untouched). |

Any other root JSON type (string, number, object without a valid `elements` array, etc.) is rejected with a logged error and the load aborts without modifying the simulation.

### Compatibility in both directions

- **Old files, new build** — covered by the version-0 rows above. Both legacy layouts still load unchanged.
- **New files, old build** — safe. A build predating this field reads the root by looking up `identifier`, `deltaT` and `elements` by name (`root.contains(...)`); it never enumerates root keys or rejects unrecognized ones, so the extra `formatVersion` key is simply ignored. A `.dnf` saved by the current build therefore still loads correctly in an older one.

## Element object — common fields

Every entry in `elements` has these common fields when applicable; 2D-only fields may be omitted from 1D files:

| Key | Type | Description |
|---|---|---|
| `uniqueName` | string | The element's unique name (`ElementIdentifiers::uniqueName`) — used to resolve `inputs` references and must be unique within the file. |
| `label` | `[int, string]` pair | The `ElementLabel` enum value and its string form, e.g. `[1, "neural field"]`. Only the **string** is used on load (via a reverse lookup in `element::ElementLabelToString`); the integer is informational. |
| `x_max` | int | Field size (`ElementDimensions::x_max`). |
| `d_x` | number | Spatial step size (`ElementDimensions::d_x`). |
| `y_max` | int | 2D field size along y. Present for `*_2D` elements; defaults to `1` on read when absent (e.g. in 1D-only files). |
| `d_y` | number | 2D step size along y. Present for `*_2D` elements; defaults to `1.0` on read when absent. |
| `inputs` | array of `[uniqueName, component]` pairs, or `[]`/`null` | One entry per connected input: the source element's `uniqueName` and which of its components (e.g. `"output"`, `"activation"`) to read. Empty when the element has no inputs. |

Element-specific fields (below) are added directly alongside these common fields — there's no separate "parameters" sub-object.

### A real example

From `data/memory-trace/memory-trace.dnf` (trimmed to one element, with `formatVersion` shown as the current build would write it — the committed sample files predate the field and load as version 0):

```json
{
    "formatVersion": 1,
    "identifier": "memory-trace",
    "deltaT": 1.0,
    "elements": [
        {
            "uniqueName": "nf 1",
            "label": [1, "neural field"],
            "x_max": 100,
            "d_x": 1.0,
            "inputs": [
                ["mhk 1", "output"],
                ["gs nf 1 20.000000", "output"],
                ["nn 1", "output"],
                ["gs nf 2 80.00000", "output"]
            ],
            "tau": 59.16888333852977,
            "restingLevel": -7.371159004013208,
            "activationFunction": {
                "type": "sigmoid",
                "x_shift": 0.0,
                "steepness": 5.0
            }
        }
    ]
}
```

(Key order in an actual file follows `nlohmann::json`'s alphabetical object key ordering, not insertion order — the example above is reordered here for readability.)

## Element-specific fields, by label

These are the keys `elementToJson()` writes for each supported `ElementLabel`; some are optional or fall back to a documented default on load (as noted per field). Field names match the corresponding `*Parameters` struct members 1:1 (see [Element Reference](Element-Reference) for what each means).

**Unless a field is explicitly noted below as optional or defaulted, it is required for that element's label.** `jsonToElements()` reads every one of these fields with `json::at()`, which throws `json::out_of_range` if the key is absent; that exception is caught by `buildElementsOrRollBack()` and reported as a malformed file (see [Error handling on load](#error-handling-on-load)) rather than being undefined behavior. The exceptions are `activationFunction` (see `neural field` below) and `input_x_max`/`input_d_x` on `field coupling`/`gauss field coupling` (see below), both of which fall back to a documented default when omitted — plus `couplings` (`gauss field coupling`) and `onTimes` (`timed gauss stimulus`/`timed gauss stimulus 2d`), which fall back to an empty array when absent or malformed rather than failing the load. The latter two are pre-existing tolerant behavior, not a considered default the way the first two are.

### `neural field` / `neural field 2d`

| Key | Maps to |
|---|---|
| `tau` | `NeuralFieldParameters::tau` |
| `restingLevel` | `NeuralFieldParameters::startingRestingLevel` |
| `activationFunction` | Object: `{"type": "sigmoid"\|"heaviside"\|"abs_sigmoid", "x_shift": ..., "steepness"\|"beta": ...}`. `heaviside` has no steepness/beta field. If missing/null on load, defaults to `SigmoidFunction(0.0, 10.0)`. |

Note: the 2D variant's loader (`case element::NEURAL_FIELD_2D`) only recognizes `"sigmoid"` and `"heaviside"` — `"abs_sigmoid"` is written for 1D fields but there's no corresponding read branch for 2D fields in the current code.

### `gauss kernel` / `gauss kernel 2d`

`width`, `amplitude`, `amplitudeGlobal`, `circular`, `normalized`.

### `mexican hat kernel` / `mexican hat kernel 2d`

`widthExc`, `amplitudeExc`, `widthInh`, `amplitudeInh`, `amplitudeGlobal`, `circular`, `normalized`.

### `oscillatory kernel` / `oscillatory kernel 2d`

`amplitude`, `decay`, `zeroCrossings`, `amplitudeGlobal`, `circular`, `normalized`.

### `asymmetric gauss kernel`

`width`, `amplitude`, `amplitudeGlobal`, `timeShift`, `circular`, `normalized`.

### `asymmetric gauss kernel 2d`

`width`, `amplitude`, `amplitudeGlobal`, `timeShift_x`, `timeShift_y`, `circular`, `normalized`.

### `gauss stimulus` / `gauss stimulus 2d`

1D: `width`, `amplitude`, `position`, `circular`, `normalized`.
2D: `width`, `amplitude`, `position_x`, `position_y`, `circular`, `normalized`.

### `timed gauss stimulus` / `timed gauss stimulus 2d`

Same fields as `gauss stimulus`/`gauss stimulus 2d`, plus `onTimes`: an array of `[tStart, tEnd]` two-element arrays. **Optional**: absent or non-array `onTimes` falls back to an empty vector on load rather than failing (pre-existing tolerant behavior, not a considered default).

### `normal noise` / `normal noise 2d`

`amplitude`.

### `correlated normal noise` / `correlated normal noise 2d`

`amplitude`, `width`, `circular`. (Note: `correlatedNormalNoise` is registered in `ElementFactory` and read/written by `SimulationFileManager`, but does not currently have an entry in the `Elements`/`Element-Reference` wiki pages' label table.)

### `boost stimulus` / `boost stimulus 2d`

`amplitude`, `isActive`.

### `memory trace` / `memory trace 2d`

`tauBuild`, `tauDecay`, `threshold`.

### `field coupling`

| Key | Maps to |
|---|---|
| `learningRate` | `FieldCouplingParameters::learningRate` |
| `learningRule` | `LearningRule` enum, serialized as its underlying integer |
| `scalar` | `FieldCouplingParameters::scalar` |
| `input_x_max`, `input_d_x` | `FieldCouplingParameters::inputFieldDimensions` (`x_max`, `d_x`). **Optional**: `FieldCouplingParameters` defaults `inputFieldDimensions` to `ElementDimensions{}` (`x_max` 100, `d_x` 1.0) — if either key is absent on load, that default is used instead of failing the load. |

The weight matrix itself is **not** embedded in the `.dnf` file — see [Weight files](#weight-files-fieldcoupling) below.

A `FieldCoupling`'s DELTA-rule teaching signal is stored as an ordinary interaction entry,
distinguished only by its component string: `["teacherFieldName", "target"]` instead of the usual
`["sourceName", "output"]`. Older files never contain `"target"` and are unaffected; a file
containing `"target"` loaded by a build that predates the DELTA rewrite will fail when that build
looks up a `"target"` component on a plain `NeuralField`.

A coupling's input or target slot may also be wired from a source's *Activation* pin instead of
its default Output pin, using the component strings `"activation"` (input slot) and
`"target:activation"` (target slot) respectively — e.g. `["teacherFieldName",
"target:activation"]`. `"target"` and `"output"` keep their original meaning unchanged; a file
containing only those strings is unaffected by this addition.

### `gauss field coupling`

| Key | Maps to |
|---|---|
| `circular`, `normalized` | `GaussFieldCouplingParameters` |
| `input_x_max`, `input_d_x` | `inputFieldDimensions`. **Optional**, same `ElementDimensions{}` (100, 1.0) default as `field coupling` above when either key is absent. |
| `couplings` | Array of `[x_i, x_j, amplitude, width]` 4-element arrays, one per `GaussCoupling`. **Optional**: absent or non-array `couplings` falls back to an empty vector on load rather than failing (pre-existing tolerant behavior, not a considered default). |

### `resize` / `resize 2d`

| Key | Maps to |
|---|---|
| `method` | `InterpolationMethod` enum (`LINEAR`=0, `NEAREST`, `CUBIC`), serialized as its integer value |
| `input_x_max`, `input_d_x` | `inputDimensions.x_max`, `.d_x` |
| `input_y_max`, `input_d_y` (2D only) | `inputDimensions.y_max`, `.d_y` |

On load, if `input_x_max`/`input_d_x` (and, for 2D, `input_y_max`/`input_d_y`) are absent — e.g. in a hand-edited or older file — the loader falls back to the element's own output dimensions (`x_max`/`d_x`/`y_max`/`d_y`) rather than failing.

### `collapse`

`compression` (`CompressionType` enum integer: `SUM`, `AVERAGE`, `MAXIMUM`, `MINIMUM`), `keepAxis` (`ProjectionAxis` enum integer: `X`, `Y`), `input_x_max`, `input_d_x`, `input_y_max`, `input_d_y` (same missing-key fallback behavior as `resize`).

### `expand`

`broadcastProfileAxis` (`ProjectionAxis` enum integer), `input_x_max`, `input_d_x` (same missing-key fallback behavior).

## Weight files (`FieldCoupling`)

`FieldCoupling` weight matrices are **not** stored inside the `.dnf` JSON. Instead:

- On save, `SimulationFileManager::saveElementsToJson()` calls `fc->writeWeights()` for every `FieldCoupling` element, writing `<simDir>/<coupling_uniqueName>_weights.txt` — a plain-text, whitespace-separated matrix (input rows × output columns, row-major) alongside the `.dnf` file.
- On load, weights are resolved relative to **the directory containing the `.dnf` file** (`std::filesystem::path(filePath).parent_path()`), and read back via `tryReadWeights()`, which silently starts from zero weights (logging an info message) if no matching `_weights.txt` file exists rather than treating it as an error.

---

## Default output layout

When `SimulationFileManager` is constructed with an empty path (the default when calling `simulation->save()`/`simulation->read()` with no argument), files are organized as:

```
data/<identifier>/
    <identifier>.dnf                 # this schema
    <coupling_name>_weights.txt      # one per FieldCoupling element
```

See [Architecture → JSON persistence](Architecture#json-persistence) and [Simulation → Persistence](Simulation#persistence-save--load) for how this ties into the rest of the simulation lifecycle, and `data/` in the repository root for real examples (e.g. `data/multi-peak/`, `data/memory-trace/`, `data/detection-instability/`) you can open directly.

## Error handling on load

`loadElementsFromJson()` is defensive rather than exception-throwing for malformed *simulation-level* metadata and structural issues — see [Troubleshooting](Troubleshooting#loading-a-dnf-file) for the exact log messages and what triggers each one (unreadable file, invalid JSON, non-array `elements`, duplicate `uniqueName` entries, interactions referencing elements that failed to load, and unrecognized `label` values). A `formatVersion` that isn't a whole number `>= 0` is handled the same way — see [Schema version](#schema-version).

A missing **required** element-specific field (anything in the tables above not marked optional/defaulted) is a different case: `jsonToElements()` reads it with `json::at()`, which throws `json::out_of_range`. `buildElementsOrRollBack()` catches that, logs `Invalid simulation file: could not build the elements of <path> (<exception text>) - load aborted.`, removes any elements this load already added, and returns without modifying the simulation further — the same rollback path used for constructor-rejected elements (see the [Troubleshooting](Troubleshooting#loading-a-dnf-file) table).
